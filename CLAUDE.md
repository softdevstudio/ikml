# iKML: where the next session starts

iKML opens KML, KMZ, GeoJSON, GPX and CSV files, shows what's inside, flags what's
broken, reports what a conversion loses, and writes cleaned copies. Go,
standard library only.

- `open.go` detects the format by content; `kml.go`, `geojson.go`, `gpx.go`
  and `csv.go` parse into the shared model in `model.go`. GPX and CSV keep
  the source bytes (`gpxInfo.raw`, `csvInfo.raw`): GPX to GPX and CSV to CSV
  write them back unchanged, splicing in only the coordinates clean fixed; `gpx.go` and `csv.go` also hold their writers and loss
  reports.
- `analyze.go` runs the checks; `issues.go` holds the issue code table,
  which is also the source of REFERENCE.md (`go run ./internal/refgen > REFERENCE.md`).
- `report.go` builds the inspect report; `loss.go` the conversion loss
  report; `clean.go` the safe fixes; `write.go` writes GeoJSON, KML and KMZ;
  `preview.go` thins shapes for the browser preview.
- `cmd/ikml` is the CLI; `batch.go` is `check DIR`. `action.yml` is the
  GitHub Action, tested by `.github/workflows/action-test.yml`. `wasm/` is the WebAssembly entry point and `web/`
  the browser inspector (`ikml.js`, `index.html`); `scripts/build-wasm.sh`
  builds it, `scripts/wasm-smoke.mjs` tests it in Node.
- `testdata/` holds hand-written fixtures; the KMZ ones are generated by
  `go run ./internal/fixturegen` from `internal/fixtures`.

Site repo: github.com/photozeitgeist/ikml.com (Hugo, Launch template,
content and config values only; never touch the theme). The site's
in-browser inspector is a copy of `web/` in its `static/tool/` folder;
update it from the release's `ikml-web.zip` whenever the engine changes, and
check with `scripts/check-site-tool.sh SITE_DIR` (the site repo is private,
so this runs from a session, not CI).

## Workflow (low maintenance)

- Pull before working: ChatGPT/Codex also works on this repo (see AGENTS.md).
- The owner does not publish releases. Raise the version in `VERSION` and
  `const Version` in `cmd/ikml/main.go`, add a `CHANGELOG.md` section, push to
  main. When CI is green, `release.yml` builds Linux/macOS/Windows archives
  and `ikml-web.zip`, smoke-tests them, checks the whole release with rmqa
  (`rmqa.toml`), tags `vX.Y.Z` and publishes. Then watch the run, check the
  release files and links, and run a downloaded binary.
  `scripts/check-version.sh` keeps the places in step.
- Every number on the site comes from `test/results/`, written by
  `scripts/record-results.sh`. Re-record after any change that could move a
  number, and update the site from the new files.
- An independent review agent looks at code and site before a release is
  called done.
- main is the default branch. No side branches.
- GitHub job logs can't be downloaded from these sessions, but annotations
  can. Workflows print `::error::` lines for that reason. Read the real error
  before any rerun; at most two fix-and-retry rounds on one failure, then
  stop and report what's known and the options.
- Issue codes are a public interface: never rename one. Add new codes to
  the table in `issues.go` and regenerate REFERENCE.md.
- Don't push to main while a release run is going. GitHub refuses the job's
  token when it tags a commit that's no longer main's newest one, so the
  release must tag main's head.
- The release checks itself with a pinned rmqa release (see release.yml).
  Raise the pin when rmqa ships a fix that matters here.
- Commit and push after each finished piece of work, not at the end.

## Gaps and to-do

Known gaps, not planned yet:

- No Shapefile or GML input or output (GPX and CSV from 0.2).
- No reprojection: a GeoJSON `crs` other than WGS 84 is reported, not converted.
- NetworkLinks are listed, never fetched.
- 3D models and overlays are counted and kept in KML, not inspected further.
- No editing beyond the safe fixes in `clean`.
- The browser preview has no base map, by design (no network requests).

## Done: iKML 0.2, the files people actually have (softdev-plan item 23, approved by YK 2026-11-04)

What and why: the files people bring to a map tool are mostly GPX from a watch or an app and CSV from a spreadsheet, and iKML can open neither. Content and docs repos with map files have no CI gate. The site's copy of the browser tool can drift from the engine unnoticed.

Design decisions:
- Phase A, GPX in and out.
  - Detected by content: XML whose root element is `gpx` (GPX 1.0 or 1.1, any namespace prefix) is `FormatGPX`; other XML stays KML.
  - Model: each `wpt` is a Point placemark (name, desc, time, ele); each `rte` a LineString placemark; each `trk` one placemark, a Track (coordinates with times) per `trkseg`, or a LineString when the segment has no times; several segments make a MultiTrack. Waypoint, route and track elements other than those (cmt, src, sym, type, number, link) become fields, so conversions keep them as properties or ExtendedData.
  - Everything else is kept verbatim for GPX output: the root's namespace declarations and creator, `metadata`, every `extensions` element, and per-point children other than ele and time (Garmin and Strava heart rate, cadence, temperature and power live there), kept per point.
  - GPX to GPX keeps all of it. GPX to GeoJSON, KML or KMZ reports what goes: point extensions by element name with counts (hr, cad, atemp, power), other per-point elements, route point names and details, metadata, and extensions on waypoints, routes and tracks; and what is kept in another form (segments as a MultiTrack, fields as properties).
  - Writing GPX from KML, KMZ or GeoJSON: points become `wpt` (name, desc, time, ele), lines and tracks become `trk` with one `trkseg` per line (times from a Track or GeoJSON coordTimes), polygons and the rest are reported lost, as are fields, styles and folders. GPX 1.1 output, creator "iKML".
  - New issue codes (never renamed later): `gpx-time-invalid` (a time that isn't RFC 3339), `gpx-time-backwards` (a point earlier than the one before it in a segment), `gpx-version` (version other than 1.0 or 1.1). Coordinate range checks are shared with the other formats.
  - `clean` on GPX (and CSV) applies --fix-swapped only; repeated points in a GPS track are real readings and stay, as for gx:Track. Everything verbatim stays.
- Phase B, CSV and batch.
  - CSV in: detected when the content isn't XML or JSON and the first line, split by `,`, `;` or tab (the one giving the most columns), names a latitude and a longitude column (lat/latitude/y and lon/lng/long/longitude/x, case-insensitive). Each row is a Point; name/title, description/desc, time/timestamp, and ele/elevation/alt/altitude columns map to the model, every other column to a field. New codes: `csv-no-coordinates` (no lat and lon header: unreadable), `csv-bad-row` (a row whose coordinates aren't numbers, skipped), `csv-ragged-row` (a row with a different column count).
  - CSV out: one row per point (Point placemarks and waypoints), columns name, lat, lon, then ele, time and description when any point has them, then every field in first-seen order. Lines, tracks and polygons are reported lost with counts. RFC 4180 quoting, UTF-8, comma.
  - `ikml check DIR [--json] [--strict]`: walks the folder (symlinks not followed, files by extension .kml .kmz .geojson .json .gpx .csv, at most 10000 files), checks each, prints one line per file and the totals, or one JSON object with `files` and `totals`. Exit 1 when any file has errors (or warnings with --strict). `ikml check FILE` keeps its 0.1 output.
  - The Action: composite `action.yml` (PXTA ACTION.md pattern as in ForgeSchema): downloads the release binary for the runner, checks SHA256SUMS, runs `ikml check PATH --json`, writes a `::error`/`::warning` annotation per issue with file and line, a job summary table, and fails on errors (`fail`, `strict` inputs; only true and false accepted). Tested by `.github/workflows/action-test.yml`: local job with a binary built from the commit on the good and bad fixtures, install job on macOS and Windows on push with a published release, download job on the published binaries after each release.
- Upkeep: `go.mod` to 1.26; the site's `static/tool/` checked against the release's `ikml-web.zip`; the browser tool accepts .gpx and .csv. Plan change: the site repo is private, so a workflow here can't read it without a token (YK's call); `scripts/check-site-tool.sh SITE_DIR` does the check from a session, at each release. Its first run found the site's ikml.wasm built locally with Go 1.24.7, matching no release.
- Done when: a Garmin Connect and a Strava GPX export (fixtures written to their documented layout, with heart rate, cadence, temperature and power extensions) round-trip GPX to GPX unchanged in content and GPX to GeoJSON and KML and back with a loss report that names exactly what went.
