# iKML: where the next session starts

iKML opens KML, KMZ and GeoJSON files, shows what's inside, flags what's
broken, reports what a conversion loses, and writes cleaned copies. Go,
standard library only.

- `open.go` detects the format by content; `kml.go` and `geojson.go` parse
  into the shared model in `model.go`.
- `analyze.go` runs the checks; `issues.go` holds the issue code table,
  which is also the source of REFERENCE.md (`go run ./internal/refgen > REFERENCE.md`).
- `report.go` builds the inspect report; `loss.go` the conversion loss
  report; `clean.go` the safe fixes; `write.go` writes GeoJSON, KML and KMZ;
  `preview.go` thins shapes for the browser preview.
- `cmd/ikml` is the CLI. `wasm/` is the WebAssembly entry point and `web/`
  the browser inspector (`ikml.js`, `index.html`); `scripts/build-wasm.sh`
  builds it, `scripts/wasm-smoke.mjs` tests it in Node.
- `testdata/` holds hand-written fixtures; the KMZ ones are generated by
  `go run ./internal/fixturegen` from `internal/fixtures`.

Site repo: github.com/photozeitgeist/ikml.com (Hugo, Launch template,
content and config values only; never touch the theme). The site's
in-browser inspector is a copy of `web/` in its `static/tool/` folder;
update it whenever the engine changes.

## Workflow (low maintenance)

- Pull before working: ChatGPT/Codex also works on this repo (see AGENTS.md).
- The owner does not publish releases. Raise the version in `VERSION` and
  `const Version` in `cmd/ikml/main.go`, add a `CHANGELOG.md` section, push to
  main. When CI is green, `release.yml` builds Linux/macOS/Windows archives
  and `ikml-web.zip`, smoke-tests them, checks the whole release with rmqa
  (`rmqa.toml`), tags `vX.Y.Z` and publishes. Then watch the run, check the
  release files and links, and run a downloaded binary.
  `scripts/check-version.sh` keeps the places in step.
- Every number on the site comes from `test/results/`, written by
  `scripts/record-results.sh`. Re-record after any change that could move a
  number, and update the site from the new files.
- An independent review agent looks at code and site before a release is
  called done.
- main is the default branch. No side branches.
- GitHub job logs can't be downloaded from these sessions, but annotations
  can. Workflows print `::error::` lines for that reason. Read the real error
  before any rerun; at most two fix-and-retry rounds on one failure, then
  stop and report what's known and the options.
- Issue codes are a public interface: never rename one. Add new codes to
  the table in `issues.go` and regenerate REFERENCE.md.
- Commit and push after each finished piece of work, not at the end.

## State

0.1.0 (2026-10-25): inspect, check, convert, clean, codes; KML, KMZ and
GeoJSON in and out; loss reports; browser version on WebAssembly.

## Gaps and to-do

Known gaps, not planned yet:

- No GPX, Shapefile, GML or CSV input or output.
- No reprojection: a GeoJSON `crs` other than WGS 84 is reported, not converted.
- NetworkLinks are listed, never fetched.
- 3D models and overlays are counted and kept in KML, not inspected further.
- No editing beyond the safe fixes in `clean`.
- The browser preview has no base map, by design (no network requests).
